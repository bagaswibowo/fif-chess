# Jev Chess

A small browser chess game against [TypeSafe](https://typesafe.ai) **Jev**.

Jev is not a chat model. You do not ask it to write `e4` as a sentence. Chess.js owns legality, check, checkmate, stalemate, and draws. This app sends Jev the position plus one [Choice](https://docs.typesafe.ai/primitives/choice.md) whose option keys are the legal UCI moves and whose descriptions are the SAN of those moves. Jev returns a probability distribution. The app applies `answers.choice` only if that key was in the legal set it sent. If the API fails, rate-limits, or returns something illegal, nothing is invented — you see an error and can retry.

## What you can do

- Play a full game in the browser. You are White by default.
- Swap colors or start a new game.
- Watch the board, the move list, and the top of Jev’s last Choice distribution after each of its turns.
- Promote and castle. Those moves are generated by chess.js (UCI such as `e7e8q` and `e1g1`). Jev can only pick among the options you listed.

## Get an API key

A TypeSafe API key is required to actually play. The board still loads without one; Jev’s turn will fail with a clear error until the key is set.

1. Create an account or sign in at [TypeSafe](https://typesafe.ai) / [the dashboard](https://console.typesafe.ai).
2. Copy an API key.
3. Put it in the environment. Never commit it.

```bash
cp .env.example .env.local
# edit .env.local and set TYPESAFE_API_KEY
```

The server reads `TYPESAFE_API_KEY` and sends it as `Authorization: Bearer`. The key is not logged and is not exposed to the browser.

Requires Node.js 20+.

```bash
npm install

```

Open [http://127.0.0.1:43173](http://127.0.0.1:43173).

## How Jev is called

Verified against the current TypeSafe docs ([index](https://docs.typesafe.ai/llms.txt), [API](https://docs.typesafe.ai/api.md), [State](https://docs.typesafe.ai/concepts/state.md), [Choice](https://docs.typesafe.ai/primitives/choice.md)):

- `POST https://api.typesafe.ai/v1/systemone`
- `Authorization: Bearer $TYPESAFE_API_KEY`
- `model`: `"jev-latest"`
- `state`: `{ "fen": "<current FEN>", "side_to_move": "white" | "black" }` — an object, which is what the docs recommend for application state. A published outside chess eval used this same pair of fields.
- One Choice question (`move`) whose `criteria` keys are legal UCI and whose values are SAN.

Choice allows at most **255** options. The known maximum of legal chess moves in a single position is 218, so a normal (and even a pathological) chess position stays under the cap. Surplus dropping is implemented only as a last resort: lowest-priority quiet moves are omitted first, and the UI flags the drop if it ever happens.

429 and 529 are surfaced as retryable errors. The app does not invent a fallback move.

## Tests

`lib/jev.test.ts` mocks the TypeSafe HTTP response and checks that:

- the outgoing body is `state` + a Choice over the position’s legal UCI moves
- an illegal or unknown `answers.choice` is rejected and never applied
- promotion (`a7a8q`) and castling (`e1g1`) are applied by chess.js

## Password gate

Jev is not called until the visitor unlocks the board. The password is not stored. Vercel holds two environment variables:

- `SITE_HMAC_KEY`, a random key
- `SITE_PASSWORD_HMAC`, the hex HMAC-SHA256 of the password under that key

Leave both empty in git. If either is missing, `/api/jev-move` refuses the call and does not touch TypeSafe. Set them in the Vercel project environment and redeploy.
